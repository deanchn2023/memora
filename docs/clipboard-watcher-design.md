# 剪贴板监控系统优化设计

## 1. 现状分析

### 当前实现
- **固定轮询间隔**: 10秒（`setInterval`）
- **简单去重**: 仅与上次内容比较
- **立即处理**: 检测到变化直接触发AI分析

### 存在的问题
1. **多次复制场景**: 用户连续复制一段内容的不同部分时，每次都触发分析，产生冗余
2. **静态频率**: 无论用户是否活跃，都是10秒轮询，可能漏检或浪费资源
3. **无人操作**: 屏幕锁定或用户离开时，仍在持续监控，不必要
4. **无暂存机制**: 无法处理"逐步复制完整内容"的场景

---

## 2. 优化方案

### 2.1 核心设计原则
- **智能暂存**: 聚合短时间内的多次复制
- **动态频率**: 根据用户活动调整检测间隔
- **状态感知**: 检测屏幕锁定/用户离开状态
- **用户可控**: 提供设置开关和参数配置

## 3. 模块详细设计

### 3.1 内容暂存器 (BufferStore)

#### 设计目标
- 聚合短时间内的多次复制操作
- 判断内容是否"完整"（不再继续追加）
- 避免对同一内容的部分片段重复分析

#### 数据结构
```javascript
class ClipboardBuffer {
  buffer: string[];        // 暂存的内容片段
  lastUpdate: number;      // 最后更新时间
  stableTimer: number;     // 稳定计时器
  isStable: boolean;       // 是否已稳定
  maxBufferSize: number;   // 最大暂存数量
  stableTimeout: number;   // 稳定判定超时（毫秒）
}
```

#### 核心逻辑

**暂存触发条件**:
- 新内容与上一条内容语义相关（如连续的段落）
- 时间间隔在 `stableTimeout` 内（默认 2 秒）
- 内容不是完全独立的新主题

**稳定判定**:
- 超过 `stableTimeout` 没有新内容 → 稳定
- 内容长度达到阈值（如 500 字）→ 提前稳定
- 用户切换窗口 → 立即稳定

**合并策略**:
- 简单拼接：`片段1\n片段2\n片段3`
- 智能去重：去除重复的前缀/后缀
- 智能合并：检测是否是同一内容的不同部分

---

### 3.2 动态频率控制器 (FreqController)

#### 设计目标
- 根据用户活动强度调整检测间隔
- 活跃时高频检测，空闲时低频
- 平衡"及时响应"和"资源消耗"

#### 频率档位（3档简化）
| 档位 | 间隔 | 触发条件 |
|------|------|----------|
| 高频 | 1s | 10秒内复制超过2次 |
| 中频 | 3s | 正常状态 |
| 低频 | 30s | 60秒无任何操作 |
| 暂停 | - | 屏幕锁定/屏保 |

#### 资源消耗分析
| 档位 | CPU消耗 | 说明 |
|------|---------|------|
| 高频 | <0.1% | 1秒轮询，与原10秒几乎无差别 |
| 中频 | <0.05% | 反而比当前10秒更低 |
| 低频 | <0.02% | 极低消耗 |

> **结论**: 动态频率带来的资源消耗极低，可以忽略不计。

#### 实现方式
```javascript
class FrequencyController {
  currentInterval: number;
  activityHistory: ActivityEvent[];
  copyHistory: number[];
  
  // 计算当前应该使用的间隔
  computeInterval(): number;
  
  // 记录用户活动
  recordActivity(type: 'mouse' | 'keyboard' | 'copy'): void;
  
  // 记录屏幕状态
  setScreenState(isLocked: boolean): void;
}
```

### 3.3 状态检测器 (StateDetect)

#### 设计目标
- 检测屏幕是否锁定
- 检测用户是否离开（基于活动）
- 检测应用是否在前台

#### 检测方式 (Electron)
```javascript
// 屏幕锁定检测
powerMonitor.on('lock-screen', () => { /* 暂停监控 */ });
powerMonitor.on('unlock-screen', () => { /* 恢复监控 */ });

// 系统空闲检测
powerMonitor.getSystemIdleState(idleThreshold);

// 应用前台状态
mainWindow.isFocused();
mainWindow.isVisible();
```

---

### 3.4 智能调度引擎 (SmartScheduler)

#### 核心流程
```
1. 检测到剪贴板变化
   ↓
2. 进入暂存器
   ↓
3. 启动稳定计时器
   ↓
4. 等待期间如有新内容 → 重置计时器并追加
   ↓
5. 稳定后 → 检查状态
   ↓
6. 屏幕未锁定 + 用户活跃 → 触发AI分析
   ↓
7. 去重检查 → 预分类 → AI调用
```

#### 状态转换图
```
[空闲] → (检测到变化) → [暂存中] → (稳定) → [分析中] → (完成) → [空闲]
           ↑                               ↓
           └── (新内容追加) ───────────────┘
```

## 4. 配置参数

### 可配置项 (Settings)
```javascript
{
  // 暂存相关
  clipboard_buffer_enabled: true,           // 是否启用暂存
  clipboard_stable_timeout: 2000,           // 稳定超时（毫秒）
  clipboard_max_buffer_size: 5,             // 最大暂存片段数
  
  // 频率相关
  clipboard_freq_enabled: true,             // 是否启用动态频率
  clipboard_freq_high: 1000,                // 高频间隔（毫秒）
  clipboard_freq_normal: 3000,              // 中频间隔（毫秒）
  clipboard_freq_low: 30000,                // 低频间隔（毫秒）
  clipboard_idle_threshold: 60000,         // 空闲判定阈值（毫秒）
  
  // 状态检测相关
  clipboard_pause_on_lock: true,            // 屏幕锁定时暂停
  clipboard_pause_on_idle: false,           // 空闲时是否暂停
}
```

## 7. 边缘情况处理

| 场景 | 处理策略 |
|------|----------|
| 用户复制同一内容多次 | 去重机制，仅处理第一次 |
| 用户复制→取消→重新复制 | 稳定计时器重置 |
| 长文本分多次复制 | 暂存合并，完整后分析 |
| 复制代码片段 → 复制自然语言 | 独立处理，不合并 |
| 屏保启动 → 用户返回 | 暂停→恢复，检查期间是否有新内容 |
| 应用在后台时复制 | 暂存，用户切换回前台后分析 |

## 8. 性能优化

### 8.1 资源占用
- 使用 `powerMonitor` 而非高频轮询检测状态
- 暂存器设置最大数量限制，避免内存泄漏
- 历史记录定期清理（保留最近1小时）
- **动态频率CPU消耗极低**: 高频模式 <0.1%，低频模式 <0.02%，几乎可以忽略

### 8.2 响应延迟
- 高频模式下响应延迟为1秒
- 重要操作（如检测到@提及）可以"插队"提前分析
- 提供"立即分析当前剪贴板"的手动触发按钮
