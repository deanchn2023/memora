## 会话分享与置顶功能设计方案

**需求**：
1. 会话分享：导出为 .ora 文件（ZIP 格式），包含会话元数据和关联 artifacts
2. 会话置顶：钉住重要会话，超过 5 条自动折叠

**设计方案文档**：`docs/design/session-sharing-pinning-design.md`

### 核心设计

#### 1. .ora 文件格式
```
.session.ora (实际为 ZIP)
├── session.json      # 会话元数据
├── messages.html     # 对话消息
└── artifacts/        # 关联产物文件
```

#### 2. 导出流程
1. 收集会话数据（元数据 + 对话历史 + 消息 HTML）
2. 扫描关联的 artifacts 文件（最近 7 天）
3. 调用主进程打包为 ZIP
4. 触发浏览器下载

#### 3. 导入流程
1. 打开文件选择对话框
2. 解压 .ora 文件
3. 读取 session.json 验证格式
4. 创建新会话并保存消息 HTML
5. 复制 artifacts 文件

#### 4. 置顶功能
- 数据结构：`pinned: true` + `pinnedAt: timestamp`
- 渲染逻辑：置顶会话在列表顶部，超过 5 条自动折叠
- 交互：点击 📌 按钮切换置顶状态

### 新增 IPC 通道
- `session:export` — 导出会话
- `session:import` — 导入会话
- `dialog:open` — 打开文件选择对话框

### 依赖
- `archiver` — ZIP 压缩/解压

### 可行性评估
- 会话分享：技术可行，中等复杂度
- 置顶功能：技术可行，低复杂度

**问题1: M-Agent (CC模式) 回答重复**
- 根因：CC 模式有两个文本发送路径：
  1. `stream_event` → `text_delta` → 增量发送 `{ event: 'delta', content: text }`
  2. `assistant` 完整消息 → `block.text` → 再次发送 `{ event: 'delta', content: fullText }`
- 两条路径的文本都被前端追加，导致整段回答出现两次
- 修复：`assistant` 消息中的 `text` 块仅在 `ccHasText === false` 时发送（即未通过 stream_event 增量发送时才补发）
- 同理修复 `thinking` 块的重复发送

**问题2: 向量检索 statusFilter 过滤 bug**
- 根因：`unifiedContextLayer.js` 中 `statusFilter: 'dormant'` 被应用到所有数据源，但 notes 的 zvec schema 没有 `status` 字段，导致所有笔记被过滤掉
- 修复：`vectorIndexManager.js` 中 `statusFilter` 仅应用于 `sourceName === 'memories'`

**问题3: hybridSearch multiQuery 失败无降级**
- 修复：multiQuery 失败时自动降级为纯 FTS 搜索（col.query）
