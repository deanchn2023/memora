## AI 助手会话历史丢失问题修复（5个严重Bug）
- **根因分析**：5个导致会话历史丢失的Bug
- **修复**：
  1. **`_finishAgentMessage()` 不保存消息**（最严重）：Agent/LLM 模式流式完成后，没有调用 `_saveCurrentSessionMessages()` 和 `_syncPushCurrentConversation()`，消息仅存在于 DOM 中。→ 在方法末尾添加两个保存调用
  2. **Agent 非流式返回也不保存**：`sendAIMessage()` 中 Agent 非流式分支缺少保存。→ 在 try 块末尾添加保存，catch 块也添加保存（避免错误时丢失之前的消息）
  3. **应用初始化不恢复消息**：`_loadChatSessions()` 恢复了会话列表和活跃ID，但不调用 `_restoreSessionMessages()` 恢复消息HTML到DOM。用户发送新消息时，`_saveCurrentSessionMessages()` 会保存空DOM覆盖localStorage。→ 在 `_loadChatSessions()` 末尾添加 `_restoreSessionMessages()`
  4. **`_syncPushConversation` 条件判断运算符优先级Bug**：`!window.SyncEngine?.isSyncing?.() === undefined` 先算 `!` 再算 `===`，永远为 false。→ 改为 `typeof window.SyncEngine?.isSyncing !== 'function'`
  5. **窗口关闭/隐藏不保存**：macOS 下 Cmd+Q 退出时无 beforeunload 保存机制。→ 添加 `visibilitychange` + `beforeunload` 事件监听自动保存

## 画像基本信息保存后丢失问题修复（4个Bug）
- **Bug 1: 重复 ID**（最严重）：`id="profileName"` 在 HTML 中出现两次——组织区域的"个人信息编辑"（line 1070）和设置页的"画像"标签（line 1496）。`document.getElementById('profileName')` 总是返回第一个（组织区域的），导致画像标签页的输入框值永远不会被 `saveProfileFromEditor()` 读取，`loadProfileEditor()` 也总是写入组织区域的输入框。→ 组织区域所有 ID 加 `orgProfile` 前缀（如 `orgProfileName`, `orgProfileNickname` 等）
- **Bug 2: 两套画像系统不同步**：组织区域 `saveProfileEdit()` 通过 `authUpdateProfile` 保存到远程认证服务器，但不同步到本地 `profile.json`。而画像标签页 `loadProfileEditor()` 从本地 `profile.json` 读取。→ `saveProfileEdit()` 成功后增加本地 `profile.json` 同步逻辑
- **Bug 3: `loadProfileEditor` 不合并远程数据**：已登录用户的姓名等存在远程 authState 中，但 `loadProfileEditor` 只读本地 profile.json。→ `loadProfileEditor()` 增加远程 authState 数据合并逻辑（远程非空字段覆盖本地）
- **Bug 4: `_settingsTabLoaded` 缓存导致刷新不加载**：画像 tab 只在首次切换时加载，保存后关闭设置再打开不重新加载。→ `saveSettings()` 和 `saveProfileEdit()` 保存后清除 `_settingsTabLoaded.profile` 缓存
- **额外修复**：`saveProfileFromEditor()` 的 `||` 逻辑（如 `value || profile.user.name`）会阻止清空字段。改为 `if (val !== '' || !profile.user.name) profile.user.name = val`

## AI 助手进度指示器Bug修复：已完成任务仍显示"智能体处理中"+计时为0
- **问题**：AI助手已回答完毕的任务，进度指示器仍显示"智能体处理中"和"0s"计时
- **根因**：
  1. **`getElementById` 多消息冲突**（主因）：`_addADPProgressStep`、`_collapseADPProgress`、计时器更新都使用 `document.getElementById('adpProgress')` 查找元素，但同一对话中多条助手消息都有 `id="adpProgress"` 的 DOM，`getElementById` 只返回第一个（旧消息的），导致当前消息的进度指示器永远无法被正确折叠
  2. **恢复历史消息时进度指示器未折叠**：`_saveCurrentSessionMessages()` 保存完整HTML（含未折叠的 `adp-progress`），`_restoreSessionMessages()` 直接插入HTML后没有折叠这些元素
  3. **`_adpTimerStart` 为 null 时计时器显示 NaN**：`_collapseADPProgress` 中 `Date.now() - null` = NaN
- **修复**：
  - 新增 `_adpCurrentMessageEl` 属性：流式开始时存储当前消息的 `messageContent` DOM 引用
  - `_addADPProgressStep()`、`_collapseADPProgress()`、计时器更新：从 `getElementById` 改为 `this._adpCurrentMessageEl?.querySelector()` 优先查找，`getElementById` 作为兜底
  - 新增 `_collapseRestoredADPProgress(container)` 方法：遍历恢复HTML中所有 `.adp-progress` 元素，折叠为完成状态（隐藏 spinner+计时器、标题改为"已完成 N 个步骤"）
  - `_restoreSessionMessages()` 插入HTML后调用 `_collapseRestoredADPProgress(chatMessages)`
  - `_collapseADPProgress()` 中计时器更新增加 `this._adpTimerStart` 空值检查
  - `_finishADPMessage()` 清理时重置 `_adpCurrentMessageEl = null`
