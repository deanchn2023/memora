## 专家团文件提交+输出修复（第二轮）

### 文件提交乱码修复
- **根因**：专家团模式只把 `textContent`（PDF/Word 等二进制文件提取出的是乱码）拼入消息文本，没有走 COS/Claw 上传获取 URL 的流程
- **一对一专家聊天正确方式**：通过 `sendADPMessage` IPC 传递 `buffer` → 主进程 COS 上传 → Claw 模式 Markdown 链接 `[文件名](url)` 传给 ADP
- **修复**：
  1. `app.js _startBackgroundGroupChat` 传递 `attachments`（含 buffer/base64/textContent）给 IPC
  2. `main.js expert-chat:start` IPC handler 中复用 COS/File Share 上传逻辑，获取 URL 后注入消息文本
  3. 上传优先级：纯文本注入 → COS 上传(Claw Markdown 链接) → File Share 上传 → 文本内容降级 → 失败提示

### 专家团无输出修复（关键 bug）
- **根因**：`GroupChatEngine._callExpert` 的 SSE 解析使用 `parsed.Content` 提取 text.delta 内容，但 ADP V2 的 `text.delta` 实际字段是 `parsed.Text` 或 `parsed.Content[0].Text`（与一对一聊天的 `send-adp-message` 一致）
- **修复**：统一使用 `parsed.Text || parsed.Content?.[0]?.Text || parsed.payload?.content?.[0]?.text` 提取 delta 文本
- 同时支持 `text.replace`、`message.done`、`message.added`、`content.added` 等事件
- `_sendEvent` 修复：`phase` 字段优先使用 `_callExpert` 传入的精确 phase，不强制覆盖为 `this.phase`
- 添加诊断日志：`_callExpert` 开始/首个 delta/完成，前端 `_handleBackgroundChatEvent` 每个事件

### 安全调用修复
- 所有 `window.ExpertSystem._addExpertMessageBubble` / `_updateExpertMessageBubble` / `_renderMarkdown` 改为可选链调用 `?.`
- 防止 ExpertSystem 未初始化时报错

## AI 助手会话历史丢失问题修复（5个严重Bug）
- **根因分析**：5个导致会话历史丢失的Bug
- **修复**：
  1. **`_finishAgentMessage()` 不保存消息**（最严重）：Agent/LLM 模式流式完成后，没有调用 `_saveCurrentSessionMessages()` 和 `_syncPushCurrentConversation()`，消息仅存在于 DOM 中。→ 在方法末尾添加两个保存调用
  2. **Agent 非流式返回也不保存**：`sendAIMessage()` 中 Agent 非流式分支缺少保存。→ 在 try 块末尾添加保存，catch 块也添加保存（避免错误时丢失之前的消息）
  3. **应用初始化不恢复消息**：`_loadChatSessions()` 恢复了会话列表和活跃ID，但不调用 `_restoreSessionMessages()` 恢复消息HTML到DOM。用户发送新消息时，`_saveCurrentSessionMessages()` 会保存空DOM覆盖localStorage。→ 在 `_loadChatSessions()` 末尾添加 `_restoreSessionMessages()`
  4. **`_syncPushConversation` 条件判断运算符优先级Bug**：`!window.SyncEngine?.isSyncing?.() === undefined` 先算 `!` 再算 `===`，永远为 false。→ 改为 `typeof window.SyncEngine?.isSyncing !== 'function'`
  5. **窗口关闭/隐藏不保存**：macOS 下 Cmd+Q 退出时无 beforeunload 保存机制。→ 添加 `visibilitychange` + `beforeunload` 事件监听自动保存

## AI 助手进度指示器Bug修复：已完成任务仍显示"智能体处理中"+计时为0
- **问题**：AI助手已回答完毕的任务，进度指示器仍显示"智能体处理中"和"0s"计时
- **根因**：
  1. **`getElementById` 多消息冲突**（主因）：`_addADPProgressStep`、`_collapseADPProgress`、计时器更新都使用 `document.getElementById('adpProgress')` 查找元素，但同一对话中多条助手消息都有 `id="adpProgress"` 的 DOM，`getElementById` 只返回第一个（旧消息的），导致当前消息的进度指示器永远无法被正确折叠
  2. **恢复历史消息时进度指示器未折叠**：`_saveCurrentSessionMessages()` 保存完整HTML（含未折叠的 `adp-progress`），`_restoreSessionMessages()` 直接插入HTML后没有折叠这些元素
  3. **`_adpTimerStart` 为 null 时计时器显示 NaN**：`_collapseADPProgress` 中 `Date.now() - null` = NaN
- **修复**：
  - 新增 `_adpCurrentMessageEl` 属性：流式开始时存储当前消息的 `messageContent` DOM 引用
  - `_addADPProgressStep()`、`_collapseADPProgress()`、计时器更新：从 `getElementById` 改为 `this._adpCurrentMessageEl?.querySelector()` 优先查找，`getElementById` 作为兜底
  - 新增 `_collapseRestoredADPProgress(container)` 方法：遍历恢复HTML中所有 `.adp-progress` 元素，折叠为完成状态（隐藏 spinner+计时器、标题改为"已完成 N 个步骤"）
  - `_restoreSessionMessages()` 插入HTML后调用 `_collapseRestoredADPProgress(chatMessages)`
  - `_collapseADPProgress()` 中计时器更新增加 `this._adpTimerStart` 空值检查
  - `_finishADPMessage()` 清理时重置 `_adpCurrentMessageEl = null`

### 根因分析
用户点击专家团发送消息后无响应，发现 5 个关键问题：

### Bug 1：群聊未创建会话 Session（最严重）
- `sendAIMessage()` 中群聊分支在 `createNewChatSession()` 之前就 `return`，导致 `_activeSessionId` 为空
- `_markChatSessionAsGroup()` 内部 `if (!appRef._activeSessionId) return;` 直接返回
- **修复**：群聊分支开头添加 `if (!this._activeSessionId) this.createNewChatSession()`

### Bug 2：双通道 `onExpertChatEvent` 重复监听
- `ExpertSystem._bindIPCEvents()` 在 `init()` 时注册了 `onExpertChatEvent`
- `app.js._startBackgroundGroupChat()` 又注册了 `onExpertChatEvent`
- 两个监听器都收到事件，造成双重处理
- **修复**：`ExpertSystem._bindIPCEvents()` 不再注册 `onExpertChatEvent`，统一由 `app.js` 按.chatId 过滤处理

### Bug 3：ADP ConversationId 上下文串扰
- 群聊启动时没有调用 `newADPChat()` 重置 `currentADPConversationId`
- 导致群聊和普通对话共享同一个 ConversationId
- **修复**：群聊启动前 `window.electronAPI.newADPChat()`；退出群聊时也重置

### Bug 4：`chatMessages` 不在 DOM 时事件静默丢失
- `_handleBackgroundChatEvent()` 中 `chatMessages` 为 null 时直接 return，消息丢失
- **修复**：添加 `_pendingGroupChatEvents` 暂存队列，切回 AI 页面时 `_replayPendingGroupChatEvents()` 重放

### Bug 5：ADP V2 ID 格式不合规
- `ConversationId` 和 `VisitorId` 需匹配 `^[a-zA-Z0-9_-]{2,64}$`
- expertId 可能含特殊字符
- **修复**：添加 `sanitizeId()` 清洗函数，`RequestId` 截断到 64 字符

### 额外修复
- `_exitGroupChatMode()` 增加：取消后台任务 + 清理监听 + 重置 ConversationId
- `_startBackgroundGroupChat()` 先 `removeExpertChatListeners()` 再注册，避免重复
- `showAIAssistantView()` 切回 AI 页面时触发暂存事件重放
