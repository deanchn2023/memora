# 2026-06-25 Memora 工作日志

## ADP 非并行模式响应内容截断修复

**问题**：ADP Agent 模式下返回的信息没有全部输出展示，表单/表格等内容在 `message.done` 事件中丢失。

**根因**：
- `_handleADPSSEEvent` 中没有处理 `message.done` 事件
- ADP V2 的 `text.delta` 只发送增量文本，而 `message.done` 包含消息的最终完整内容
- 如果 ADP 通过 `message.done` 的 `Contents[0].Text` 返回表单/表格等内容，前端不会收到

**修复**：
- `src/scripts/app.js` `_handleADPSSEEvent`：新增 `message.done` 事件处理
  - 检查 reply 类型消息的 `Contents[0].Text`
  - 如果最终文本比流式累积的更长，用最终文本替换
  - 非 reply 消息也检查是否需要补充步骤详情

## ADP 会话过期自动重试（460919）

**问题**：打开历史会话继续对话时提示 `❌ [460919] 会话ID已存在，请更换后重试`

**根因**：
- 切换到历史会话时恢复旧的 `conversationId`
- ADP 后端会话已过期，返回错误码 460919
- 前端没有自动重试机制

**修复**：
1. **SSE 错误处理**（`_handleADPSSEEvent`）：
   - 检测错误码 460919 / "会话ID已存在"
   - 清除旧 `conversationId`，更新 session
   - 1 秒后自动重试发送最后一条消息
   - `_adpRetrying` 标志防止无限重试

2. **HTTP 错误处理**（`sendADPMessage` 返回失败）：
   - 检测 `result.error` 包含 460919
   - 清除旧 `conversationId`
   - 重新调用 `sendADPMessage` 重试一次
   - 成功后显示 toast "会话已过期，已自动创建新会话"

3. **主进程**（`main.js`）：
   - HTTP 错误时读取响应体
   - 检测 460919 自动清除 `currentADPConversationId`
   - 错误信息包含错误体内容，便于前端检测

**修改文件**：
- `src/scripts/app.js` — SSE 错误处理 + HTTP 错误处理 + 保存 `_lastSendMessage`
- `main.js` — HTTP 错误体读取 + 460919 检测 + 清除 conversationId

## ADP Widget 表单内容未显示修复

**问题**：ADP Agent（如安灯需求助手、产品知识助手）返回的 widget（表单/问卷）内容未显示，用户只看到前面的文本，后面的交互式表单丢失。

**根因**：
1. `_handleADPSSEEvent` 的 `message.done` 事件中，只有 `tool_call` 类型检测 widget，`reply` 类型直接当文本处理
2. `_renderADPMarkdown` 中有 JSON 过滤正则，会删掉 widget JSON 内容
3. `_isADPWidgetContent` 检测关键词不够全面，部分 widget 结构未被识别
4. 流式渲染 `_renderADPBubble` 中没有 widget 检测，JSON 被当作 markdown 渲染导致乱码

**修复**：
1. `_finishADPMessage`：最终渲染前检测 `_adpCurrentText` 是否为 widget，是则渲染为交互式组件
2. `_renderADPBubble`：流式渲染中检测 widget JSON，显示"正在加载交互式表单..."
3. `message.done` reply 类型：增加多 Contents 支持，检测第 2+ 个 Content 中的 widget
4. `_isADPWidgetContent`：扩展关键词列表（questions/items/inputs/params/required/placeholder/label/hint）和类型检测
5. 增加 console.log 日志便于调试

**修改文件**：
- `src/scripts/app.js` — widget 检测和渲染逻辑
- `src/styles/main.css` — `.adp-widget-loading` 样式

## ADP 会话过期自动恢复上下文（460919 增强）

**需求**：session 过期时静默创建新会话，不报错，从历史记录压缩上下文代入新对话。

**实现**：

### 1. 新增 `_buildADPRetryContext()` 方法
- 优先使用 session 中已保存的 `conversationHistory`（每轮 user+assistant 摘要）
- 降级：从 localStorage HTML 消息解析
- 最多保留最近 5 轮对话
- 格式化为 `[对话历史摘要]...[当前问题]` 注入 systemRole

### 2. ADP 消息完成后保存对话历史
- `_finishADPMessage` 中新增：将本轮 user 消息(500字) + AI 回复摘要(800字) 保存到 `session.conversationHistory`
- 最多保留 10 轮（与 CC 模式一致）

### 3. SSE 错误 460919 处理（静默化）
- 不再显示 `❌` 错误，改为显示 `⏳ 会话已过期，正在恢复对话上下文...` 进度提示
- 构建 `_adpRetryContext` 存储到实例变量
- 800ms 后移除提示并重发消息
- `sendMessage` 中检测 `_adpRetryContext` 并注入到 `adpMessageData.systemRole`

### 4. HTTP 错误 460919 处理
- 构建重试上下文并追加到 `adpMessageData.systemRole`
- 重试 `sendADPMessage` 调用

**修改文件**：
- `src/scripts/app.js` — `_buildADPRetryContext` / `_finishADPMessage` 保存历史 / SSE 错误处理 / HTTP 错误处理 / sendMessage 注入上下文

## 切换会话时消息丢失修复 + 并行模式使用限制

**问题**：用户在对话进行中开启并行模式，然后新建对话，导致两个对话的消息都丢失。

**根因**：
- `_saveCurrentSessionMessages()` 使用 500ms 防抖定时器
- `createNewChatSession` 调用 `_saveCurrentSessionMessages()` 后立即切换 `_activeSessionId`
- 500ms 后防抖定时器触发 `_doSaveCurrentSessionMessages()`，但此时 `_activeSessionId` 已变为新会话
- 旧会话的消息被错误地保存到新会话的 localStorage key 下
- `stopADPGeneration()` 是异步但没有 await，导致竞态条件

**修复**：
1. 新增 `_saveSessionMessagesForSession(sessionId)` 方法：立即保存到指定会话（不防抖）
2. `createNewChatSession`：切换前先 `_saveSessionMessagesForSession(oldSessionId)`，再清除防抖定时器
3. `switchChatSession`：同样修复
4. `_toggleParallelMode`：流式响应中禁止开启并行模式
5. `createNewChatSession`：并行任务进行中显示警告 toast
6. 并行模式开启时提示"不要切换对话，否则可能丢失任务结果"

**修改文件**：
- `src/scripts/app.js` — `_saveSessionMessagesForSession` / `createNewChatSession` / `switchChatSession` / `_toggleParallelMode`
