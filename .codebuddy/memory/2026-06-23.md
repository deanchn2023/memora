# 2026-06-23 Memora 工作日志

### zvec 向量数据库整合评估
- 调研了阿里开源 zvec（嵌入式进程内向量数据库，支持稠密+稀疏向量、FTS全文检索、混合检索、WAL持久化、Node.js SDK）
- 评估结论：**强烈建议整合**。当前 Memora 搜索全部是关键词匹配（includes/searchRelated），无法理解语义等价性，召回率约30%。整合后通过向量语义检索 + FTS + 标量过滤的混合检索，召回率可达85%+，RAG上下文质量提升100%+
- 设计方案已输出到 `docs/design/zvec-integration-design.md`，已补充以下章节：
  - **向量化异步队列**：VectorizationQueue 异步处理，用户操作零阻塞，5秒聚合+批量Embedding+失败重试
  - **统一上下文层(UnifiedContextLayer)**：每次AI对话/任务自动向量检索并注入相关上下文，覆盖ADP/LLM/CC/定时任务全模式，无需手动选文件
  - **Prompt优化器审计日志**：新增prompt_optimization审计类别，记录优化前后通过率、失败模式、改进项、行为信号
  - **记忆激活机制**：活跃度评分模型(检索命中+时间衰减+用户交互+AI引用)，短期→长期晋升，90天未用沉睡降权，主动推荐相关记忆
  - **AI原生六大原则**：自动感知/自动检索/自动进化/自动激活/全模式覆盖/透明可观测
  - 实施计划更新为4周（Phase1向量基础+异步队列 → Phase2统一上下文层 → Phase3搜索RAG → Phase4记忆激活+审计）
  - **向量数据与原始数据追溯设计**（第十六章）：三层关联机制（ID绑定→来源引用→对话内引用），前端三层可追溯UI（来源Badge→详情面板→内联引用跳转），一致性校验（孤儿向量清理+content_hash变更检测），审计日志记录完整引用链路
  - **借鉴5个优秀智能体平台设计**（第十七章）：WorkBuddy(渐进式加载+身份感知+跨会话连续性)、Claude Code(向量检索即工具+权限控制)、Hermes(语义去重+反馈驱动优化)、CodeBuddy(规则向量化)、MCP架构(向量检索暴露为MCP Server)。新增 rules_vec/sessions_vec/identity_vec 三个Collection。
  - **v3.1 开发路线图**（第十八章）：4 Phase / 5 周，已提交到 git (commit 3ce7f79)

### 重大修复：本地上下文注入系统完整实现
**问题**：设计文档 `docs/design/local-context-injection.md` 已写好，LLM 意图分类 IPC `context:classify-intent` 已实现，但渲染进程的 `_retrieveLocalContext()` 和 `_retrieveLocalContextFallback()` 方法**从未实现**，调用时抛错被 catch 静默吞掉，导致上下文注入完全失效。

**修复内容**：
1. **实现 `_retrieveLocalContext(classification)`**：根据 LLM 分类结果并行检索 6 种本地数据：
   - 画像（profile.get）→ 待办任务（dbGetTasks，status 字段过滤）→ 记事本（notebookSearch/notebookGetNotes）→ 记忆（getMemories，本地关键词过滤）→ 知识（knowledgeSearchLocal，返回 results 字段）→ 人脉（relationshipGetAll，返回 {persons,relations}）
   - 每种数据有 token 预算截断（记事本 500 字/条、记忆 300 字/条等）
   - 时间范围过滤 `_filterByTimeRange()` 支持 today/yesterday/this_week/7d/30d 等
2. **实现 `_retrieveLocalContextFallback()`**：兜底策略，带 profile + 最近 5 条 pending 任务
3. **上下文注入提取到所有模式共享位置**：原代码只在 ADP 分支内执行上下文注入，CC 和 LLM 模式无注入。已提取到 `sendAIMessage` 的 try 块开头，三种模式统一执行。
4. **CC 模式**：`ccInvoke` 的 `systemRole` 从 `options.systemRole` 改为 `localContextSystemRole || options.systemRole`
5. **LLM/Agent 模式**：`localContextSystemRole` 拼接到消息前部
6. **并行模式**：`_sendParallelMessage` 也注入上下文

**需求**：剪贴板识别待办/记事项时，结合 SMART 原则检查信息完整性。不够 SMART 的补全后创建，无法补全的标注缺失。记事本标题使用 AI 提炼的摘要标题，不使用原文截断。

**修改文件**：
1. `prompts/task_recognition_v2.0.md` — 新增 SMART 评估章节（S/M/A/R/T 五要素定义、评估流程、优化规则、标题提炼规则），输出格式新增 `smart_level`/`smart_missing`/`smart_optimized` 字段，硬性规则更新
2. `prompts/memory_extraction_v2.0.md` — 新增 SMART 评估，输出格式新增 `smart_level`/`smart_missing` 字段，硬性规则更新
3. `main.js` — 剪贴板保存记事本时：传递 AI title（不再用原文截断）、添加 SMART 标签到 tags、保存 smartLevel/smartMissing/smartOptimized 到 analysis；记忆保存时也保存 smartLevel/smartMissing 到 metadata；analyze-task 返回也包含 SMART 字段
4. `src/scripts/notebook.js` — `extractTitle()` 改进：支持 markdown 标题提取、短文本直接用、句号断句、标点处截断
5. `src/scripts/app.js` — `getAnalysisStatusTag()` 展示 SMART 标签（绿色SMART/橙色待完善/红色信息不全），hover 显示缺失要素
6. `src/styles/main.css` — 新增 `.tag-smart-full`/`.tag-smart-partial`/`.tag-smart-insufficient` 样式

SMART 标签设计：
- `SMART`（绿色）：五要素齐全
- `待完善`（橙色）：缺1-2个非关键要素，hover 显示缺失项
- `信息不全`（红色）：缺3个以上要素，信息零散碎片
**问题**：CC 模式（Claude Agent SDK）设置 `permissionMode: 'default'`，但未提供 `canUseTool` 回调。SDK 遇到需要权限的工具操作（如 Write 写入新目录、Bash 执行命令）时无法向用户弹出权限请求，导致静默拒绝。用户看到 AI 说"需要你授权，系统应该已经弹出权限请求了"但实际没有弹窗。

**修复**：

   - 通过 `ipcMain.once('cc:permission-response:${requestId}')` 等待用户响应
   - 120 秒超时自动拒绝，支持 abort 信号
   - 内存缓存 `_ccAllowedToolsCache` 实现用户"总是允许"选项
2. `preload.js`：暴露 `onCCPermissionRequest`/`removeCCPermissionRequestListeners`/`ccPermissionResponse` 三个 API
3. `app.js`：实现 `_showCCPermissionDialog()` 弹窗（Apple Design 风格），显示工具名/操作详情，提供"允许"/"总是允许"/"拒绝"三个按钮
