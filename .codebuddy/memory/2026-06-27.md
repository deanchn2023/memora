## 剪贴板待办任务智能路由到专家 Agent 设计文档

**需求**：剪贴板识别待办任务后，判断是否可由专家 Agent 自动处理，自动调用专家处理并将结果关联到记事本。

**设计文档**：`docs/design/clipboard-expert-auto-process-design.md`

### 核心设计

1. **L3 专家匹配**：在现有 L1（意图分类）→ L2a（任务提取）之后，新增 L3（专家匹配）
   - 输入：任务标题/描述 + 所有专家的 intro + quickAccesses
   - AI 判断：是否可自动处理 + 匹配哪个专家 + 建议的发送 Prompt
   - 输出：`{ can_auto_process, expert_id, confidence, suggested_prompt }`

2. **自动处理流程**：
   - 匹配到专家 → 通知前端 → 切换到 AI 助手 → 选中专家 → 创建会话 → 自动发送
   - 浮动通知卡片显示匹配结果和进度

3. **记事本关联**：
   - 笔记新增 `linkedSessionId` / `linkedExpertId` / `agentProcessed` 字段
   - 记事本列表显示"🤖 已由 AI 专家处理"标识
   - 点击"查看结果 →"跳转到专家会话

### 关键文件
- 专家能力描述来源：`expert.intro` + `expert.quickAccesses[].label`
- 任务识别 Prompt：`prompts/task_recognition_v2.0.md`

## 剪贴板任务自动路由到专家 Agent — 实现完成

**状态**: ✅ 已实现

### 实现内容

#### 1. 主进程 (main.js)
- 新增 `_matchExpertForTask(task)` 函数：调用 AI 匹配专家
- 在 `analyzeClipboardText` 中，任务保存后自动调用专家匹配
- 匹配置信度 ≥ 0.7 时通知前端 `clipboard:expert-matched`
- 同时更新笔记的 `analysis.expertMatched` 标记

#### 2. Prompt 模板 (prompts/clipboard_expert_match.md)
- 输入：任务标题/描述 + 所有专家的 intro + quickAccesses
- 输出：`{ can_auto_process, expert_id, confidence, suggested_prompt }`
- 不可自动处理的判断：人工沟通/物理操作/人工决策/敏感信息/时间驱动

#### 3. 渲染进程 (src/scripts/app.js)
- `_handleExpertMatchedTask`：接收匹配事件 → 显示通知 → 切换到 AI 助手 → 选中专家 → 创建会话 → 自动发送
- `_showExpertMatchNotification`：浮动通知卡片（8秒自动消失）
- `_linkSessionToNote`：会话与记事本双向关联
- `jumpToExpertSession`：从记事本跳转到专家会话
- 记事本渲染添加"🤖 XX已处理 · 查看结果 →"标识

#### 4. Preload (preload.js)
- 新增 `onClipboardExpertMatched` / `removeClipboardExpertMatchedListeners`

#### 5. CSS (src/styles/main.css)
- `.expert-match-notification`：浮动通知卡片样式
- `.note-agent-badge`：记事本中的 Agent 标识
- `.note-agent-jump`：跳转按钮样式

### 数据流
```
剪贴板 → AI 识别为任务 → L3 专家匹配
  → 匹配到（confidence ≥ 0.7）
    → 通知前端 → 切换 AI 助手 → 选中专家 → 创建会话 → 自动发送
    → 笔记标记 expertMatched → 记事本显示"🤖 已处理"
    → 用户点击"查看结果"→ 跳转到专家会话
  → 未匹配 → 按普通待办保存
```
