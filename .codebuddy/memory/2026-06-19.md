### 9. M-Agent 子任务轮询方案设计
- 文档：`docs/design/subtask-polling-design.md`
- **问题**：M-Agent 启动 deep-research 异步工作流后返回 task_id，CC query 结束，但后台任务仍在运行，无人轮询状态和推送结果
- **根因**：CC SDK `query()` 是同步迭代器，agent 说"任务已启动"并结束后，SDK 认为"工作完成"。deep-research 工作流在火山引擎后台运行，Memora 无感知
- **三种方案**：
  - A（推荐快速实现）：应用层轮询 — CC query 完成后解析 task_id，main.js 启动定时器轮询火山引擎 API，通过 `cc:stream` 推送进度
  - B（长期）：MCP Server — 构建 DeepResearch MCP Server，提供 start/wait/query/cancel 四个工具，agent 调用 wait_research 阻塞式接收流式进度
  - C（最轻量）：Agent Prompt 优化 — 指示 agent 不要在启动异步任务后立即返回，而是用 WebFetch 工具定期轮询
- **关键阻塞**：需确认火山引擎 Deep Research API 的状态查询 endpoint 和返回格式
- **排查方法**：检查 CC SDK 是否内置 deep-research、检查 agent system prompt/skill 配置、下次执行时打印完整 block 日志
