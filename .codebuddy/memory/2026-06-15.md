## 日历拖拽功能修复

**根因**：`body` 上 `user-select: none` 阻止了 HTML5 Drag & Drop 的 `dragstart` 事件，导致拖拽完全无法启动。

**方案**：将 HTML5 Drag & Drop 全部替换为自定义 mousedown/mousemove/mouseup 实现：
- 新增 `_bindDraggable(el, taskId)` 统一注册拖拽源
- 新增 `_handleDragMove` / `_handleDragEnd` 处理全局拖拽
- 新增 `_createDragGhost` 创建拖拽幽灵浮层
- 新增 `_highlightDropTarget` / `_executeDrop` / `_cleanupDrag` 完整拖拽生命周期
- 移除所有 HTML5 drag/drop 事件绑定（`bindDayViewDrop`, `bindDropEvents`, `dragstart`/`dragend`/`dragover`/`drop`）
- CSS 修复：`.task-block`/`.week-task`/`.month-task-tag` 添加 `-webkit-user-drag: element; user-select: auto;`

拖拽行为：
- 日视图：拖拽更新小时级时间（30分钟精度）
- 周/月视图：拖拽只改天级别，保留原有时分不变

## 洞察-知识库拖拽导入重复文件修复

**根因**：两个 `drop` 事件处理器同时触发，导致一个文件被导入两次：
1. `insightView` 上的 `drop` → `multimodalImportBuffer`（Buffer 方式导入一次）
2. 事件冒泡到 `.main-view` 上的全局 `drop` → `multimodalImport`（文件路径方式再导入一次）

**修复**：
- `insight.js`：`container` 的 `drop` handler 添加 `e.stopPropagation()` 阻止事件冒泡
- `app.js`：全局 `mainView` 的 `drop` handler 改用 `Insight._importDroppedFiles()` 代替直接调用 `multimodalImport`（渲染进程 `file.path` 可能为空）

## 剪贴板合并文本 AI 优化

**需求**：用户连续多次复制的内容，缓冲区合并时不要简单拼接，应用 AI 优化为通顺完整的表述，保存时标注"从剪贴板 N 次复制的内容拼接优化"。

**修改文件**：
1. `clipboard/ClipboardBuffer.js`：
   - 新增 `getRawJoinedText()` 方法，返回纯拼接文本（换行连接，不含前缀和分隔线）
   - `_onStableTimeout()` 和 `_forceStable()` 回调增加 `rawJoinedText` 参数

2. `clipboard/ClipboardScheduler.js`：
   - `_onBufferStable()` 接收 `rawJoinedText` 参数，保存到 `_pendingRawJoinedText` 和 `_pendingFragmentCount`

3. `main.js`：
   - 新增 `optimizeMergedText(rawJoinedText, fragmentCount)` 函数：用 highvol 模型优化合并文本，temperature 0.2
   - `analyzeClipboardText()`：合并文本检测改为正则提取 `fragmentCount`，从 scheduler 获取 `rawJoinedText`
   - 分析成功后调用 `optimizeMergedText()`，优化后的文本+来源标注替换原 `text` 用于保存
   - 保存到记事本、记忆提取、知识萃取、前端通知全部改用 `optimizedText`

**优化原则**：不改变主要意思，只让句子更流畅更完整，去掉重复表述，保留所有关键信息

## 笔记图片下载 404 修复

**问题**：`[Notebook] Static download failed: 404` — 客户端尝试通过静态 URL `/memora/uploads/note-images/{path}` 下载图片返回 404

**根因**：
1. 服务器上图片文件可能不存在（同步只传了元数据，文件未上传）
2. 静态 URL 无认证保护，但文件确实不在磁盘上

**修复**：`main.js` `notebook:get-image` handler 增加双重下载策略：
1. 先尝试静态 URL 下载（无认证，快速）
2. 静态 URL 失败时，fallback 到带认证的 download API：先通过 `/notes/images` 查询图片元数据找到 image_id，再通过 `/memora/sync/notes/images/{id}/download` 带 JWT 下载

**问题**：打包版 `process.env` 为空 → 用户无法登录/注册/收验证码；`DEFAULT_API_KEY` 硬编码在二进制中不安全

**修改**：
1. `main.js` `DEFAULT_AUTH_SERVERS`：`process.env.AUTH_SERVER_URL || ''` → `process.env.AUTH_SERVER_URL || 'http://121.5.164.126:3010'`（auth/toolkit），configUrl → `http://121.5.164.126:3450`
2. `DEFAULT_API_KEY`：`'ark-8884b1e5-...'` → `process.env.DEFAULT_API_KEY || ''`（打包版不内置 key，需登录从云端同步）
3. `DEFAULT_BASE_URL`/`DEFAULT_MODEL`：改为 `process.env.* || 默认值`
4. `canMakeAICall()`：添加 `!config.apiKey` 检查，无 key 时返回 false
5. `getAPIConfig()`：`dailyLimit` 无 key 时返回 0
6. `handleLogout()`：增加 `config:updated` 事件通知渲染进程刷新 UI
7. `.env`：添加 `DEFAULT_API_KEY`/`DEFAULT_BASE_URL`/`DEFAULT_MODEL` 供开发使用

**原则**：
- 云端 key（`remoteConfig`）仅存内存，不写磁盘
- 用户手动填写的 key（`getSetting()`）持久化保存，不被云端覆盖
- 退出登录云端 key 随 `remoteConfig=null` 清空
- 打包版必须登录才能使用 AI 功能
